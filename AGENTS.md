# Working in this repository

This repository distributes public methods and a local runtime. It must never contain a prospect run, real customer export, company-private profile, credentials or unredacted review corpus.

Read only the skill and references needed for the current task. Canonical contracts and registries are beside the runtime under `skills/proposition/scripts/proposition_runtime/`. Runs and upstream caches belong outside this checkout.

Use tests to reproduce a real behavior defect before correcting it. Run targeted tests while working; at promotion run the complete suite and an independent review. Do not change a requirement, score threshold or test expectation merely to obtain PASS.

A passing runtime test is not a passing client proposal. State the exact scope of each receipt. Publication, diffusion rights, completeness and creative quality are separate decisions. Never fabricate tool use, isolated review contexts, scores, account tokens or an external readback.

When maintaining this repository and freezing or changing a functional contract, skill, pipeline stage, dispatch or quality gate, read the production-validation section of `skills/proposition-quality/SKILL.md` and follow its linked procedure. Qualify the component first, integrate its canonical instructions and controls, then require a fresh isolated E2E whose complete user input is only the repository URL and the prospect website URL. Maintainer coaching, extra creative prompts or manually supplied client artifacts make a run assisted; it cannot certify autonomous production readiness. Observe without helping, inspect exact final artifacts, and record the tested repository revision and limitations. Do not claim this requirement passed from documentation or unit tests alone. Ordinary proposal execution and freezing a client's scenes do not recursively launch repository-qualification runs.

Keep the original choice of each client's visual world. No universal deck template or house-style substitution. Internal handoffs derive from the final client proposal, not the other way around.

Before a new capability trial, fill the preintegration card in the existing production-validation reference: need, current owner/pointer, proposed delta, protected gains, existing evidence, equal-work comparison and decision per sub-capability. Keep the experiment and its receipt outside this public checkout. An assisted prototype does not prove canonical integration.

After manual qualification, keep every capability in the existing matrix until an evidenced integration or explicit non-admission decision. Follow the continuity fields in that same reference; run `scripts/check_integration.py MATRIX` on resume/handoff and with `--close` before declaring the parent plan complete. A finished neighboring fix does not close pending qualifications, integrations or autonomous E2E checks. Resume the recorded authorized next action; preserve a real blocker or explicit user reprioritisation without calling unfinished work complete. This maintenance check adds no gates to ordinary client runs.
